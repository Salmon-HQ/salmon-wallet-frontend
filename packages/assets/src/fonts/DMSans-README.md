# DM Sans — modified binaries, and why

`DMSans-{Regular,Medium,SemiBold,Bold}.ttf` in this folder are **not** the
upstream files. They are generated by `scripts/dmsans.py` and differ from
upstream in exactly one way: the ten digits share one advance width per weight.

## Provenance

| | |
| --- | --- |
| Source | `upstream/DMSans-4.004[opsz,wght].ttf`, from [google/fonts `ofl/dmsans`](https://github.com/google/fonts/tree/main/ofl/dmsans) |
| Version | `Version 4.004;gftools[0.9.30]` |
| Instances | `wght` 400 / 500 / 600 / 700, `opsz` pinned at 9 |
| Modification | digit advances equalised to the widest digit, each outline shifted by half the difference so it stays optically centred; every GPOS kern pair touching a digit dropped (1079 per weight) |
| Licence | SIL OFL 1.1 — `DMSans-OFL.txt`, shipped beside the binaries |

The variable source is committed so the statics can be regenerated offline and
byte-diffed. Nothing imports it; it is not bundled.

## Why the modification

No released DM Sans has a `tnum` feature — there are no tabular glyphs to switch
to, and [googlefonts/dm-fonts#25](https://github.com/googlefonts/dm-fonts/issues/25)
has been open and unanswered since 2023. Its `1` is 342 units against a `0` at
656, so a balance ticking `$17.29 → $17.30` reflows the line on every refresh.
`font-variant-numeric: tabular-nums` and React Native's `fontVariant` can only
turn on a feature that exists; against this font they are silently no-ops. The
fix has to be in the binary, so it is.

Equal advances alone are not enough. The `kern` pairs were fitted to the
original proportional shapes, and they are *conditional* — with advances
equalised but kerning intact, `$17.29` and `$17.30` still shaped 6 units apart
and `1,234.56` and `9,999.99` 60 units apart, which is the jitter returning
through the other door. Real tabular figures are not kerned, so the script drops
every pair that touches a digit. `--check` shapes those exact strings with
HarfBuzz and fails if any pair moves.

Because the widths are baked into the advances rather than gated behind a
feature, digits are tabular unconditionally, on all three surfaces, with no call
site able to forget it. Digit width differs *between* weights (656 / 663 / 672 /
678) — that is fine, no rendered number changes weight mid-update.

## Licence compliance

DM Sans declares **no Reserved Font Name**, so OFL clause 3 does not bind and a
modified binary may keep the name. The clauses that do bind are met: the licence
travels with the binaries (clause 2), the fonts stay OFL (clause 5), and no
author's name promotes them (clause 4). Each file's `name` table records the
modification in IDs 5 and 10, so it is visible to anyone who opens the file.

## Regenerating

```bash
pip3 install fonttools
python3 scripts/dmsans.py           # rewrite the statics and both public/ mirrors
python3 scripts/dmsans.py --check   # verify tabularity and that the mirrors match
```

`packages/shared/src/theme/tabularFigures.test.ts` asserts the same property from
the JS side, straight off the shipped bytes. After an upstream DM Sans release,
replace the file in `upstream/` and re-run — and regenerate the wordmark
(`python3 scripts/wordmark.py`), which is outlined from `DMSans-SemiBold.ttf`.
