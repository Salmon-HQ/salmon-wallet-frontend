# Implementation Plan: Salmon Wallet design system in Pencil

**Branch**: `feat/041-pencil-design-system` | **Date**: 2026-10-09 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/041-pencil-design-system/spec.md`

## Summary

Draw the shipped UI (baseline: `origin/main` 31cd6541 + `feat/seeker-seed-vault`
0c037b5f) as a Pencil design system in the private SOT: a library of themed
token variables and auto-layout components (`Salmon.lib.pen`), a screens file
that imports it with platform templates and the six key flows
(`Salmon Screens.pen`), a findings report of code-vs-structure debt, and a short
`Design System.md`. Everything is generated by builder scripts run through the
headless pen CLI, from a token manifest exported by executing the shared theme
module, and checked against runtime measurements captured with the existing
Playwright and Maestro suites. No app code changes.

## Technical Context

**Language/Version**: JavaScript (Pencil `execute` builder scripts, Node ≥ 22.19 for the CLI); TypeScript run through the repo's `jiti` for the token exporter; bash for the CLI wrapper

**Primary Dependencies**: pen CLI 0.3.11 (`@pen.dev/cli`, already installed); Playwright (in repo); Maestro (installed); Jev classification (`typesafe:typesafe-ai`, `$TYPESAFE_API_KEY`). No new dependency in this repo.

**Storage**: Files in the SOT: `.pen` (JSON), `tokens.manifest.json`, `inventory.csv`, `measurements/**.json|png`, `Findings.md`

**Testing**: Variable lint (zero unbound values), token/component coverage diff, PNG export vs runtime screenshot and per-element bounds (1px templates, 2px flows)

**Target Platform**: Pencil desktop app and pen CLI on macOS; captures from headless Chromium (extension side panel) and iOS Simulator 390×844 (mobile)

**Project Type**: Design-asset pipeline (scripts + generated design files), outside the app build

**Performance Goals**: A full library rebuild from scratch runs unattended (builder chain + lint) without manual edits

**Constraints**: One writer per `.pen` file; Pencil limits in research R3 (no width/height variables, no stretch, no margin, `#RRGGBBAA`, no variants); no scripts/shaders for materials; test wallets only, never broadcast; design files never in the public repo

**Scale/Scope**: ~150 tokens (91 semantic + 39 palette + scales/type/radius/sizes); 116 DOM kit folders inventoried, the subset used by the six key flows drawn; 5 templates; 6 flows mobile in full + extension container deltas

## Phases (the order tasks will follow)

1. **Setup** — create `03-dev/Design System/` in the SOT with `tools/`,
   `measurements/`, `exports/`; `pen-run.sh`, `_helpers.js`, `empty.pen`.
   Owner installs fonts (R8).
2. **Inventory** — build `inventory.csv` from the three sources (R7); Jev first
   pass on class/platform; main-model review of low-confidence rows and a 20%
   sample; mark `in_key_flows` from the key-flow pages' import graph.
3. **Tokens** — `export-tokens.ts` → manifest + `00-tokens.js`; run on the
   library; coverage diff passes (US1 / SC-002).
4. **Runtime audit** — capture every key-flow state on both platforms
   (`capture-extension.mjs`, `capture-mobile.sh`); auto-flag DOM debt
   candidates; this precedes drawing so every component is drawn from a
   measurement (FR-013).
5. **Library** — builders `10`→`60` in dependency order, each tested on a copy,
   then run on the real file with lint + export between each (US1).
6. **Templates** — `70-templates` in the screens file after
   `import_library`; checked against measured containers within 1px (US2).
7. **Flows** — `80-flow-*` mobile in full, then `85-extension-deltas`;
   exports in both themes compared with captures within 2px (US3).
8. **Findings** — consolidate auto-flags, twin divergences, DESIGN.md
   mismatches and drawing-time differences into `Findings.md`; spot-check three
   (US4 / SC-005).
9. **Note** — `Design System.md` per SOT frontmatter rules, with the baseline
   record and the "keep in sync" steps (US5).

Phases 2–4 can run in parallel (different outputs); 5 depends on 2–4;
6–7 on 5; 8 on 4–7.

**Structure Decision**: Design files and tooling live together in the SOT
folder, so `Salmon.lib.pen` and `Salmon Screens.pen` sit side by side and the
import path is the stable relative `Salmon.lib.pen` (R1). This repo carries
only the spec set.

## Owner decisions (resolved 2026-10-09)

- **D1 — Extension surface.** Confirmed: the extension templates are _Side
  panel_ (what the toolbar opens) + _Approval window_ (`popup.html`, dApp
  approvals only) + extension sheet (R5; spec FR-009). (Phase 6)
- **D2 — Where the tooling lives.** All tooling lives in the SOT,
  `03-dev/Design System/tools/`; nothing but the spec set is committed to this
  repo (R10). (Phases 1, 3, 4)
- **D3 — `product.pen`.** Used as a structural reference while building, never
  as a colour source (R11). When the 041 work is finished it is deleted:
  moved to the macOS Trash, never removed with `rm`, and only after the flows
  that replace it exist and the owner has seen them. That is the last task.

## Risks

- **Pencil CLI behaviour drift**: the import/theme behaviour (R1) is verified
  on 0.3.11 only; pin the CLI version in `Design System.md` and re-run the
  probe after upgrades.
- **Fonts**: comparisons are meaningless until the shipped fonts are installed
  in Pencil (R8).
- **Mobile style data**: Maestro gives bounds, not styles; mobile structural
  causes are read from source, so mobile findings take longer per item.
- **Baseline moves**: `feat/seeker-seed-vault` may gain commits during the
  work; the baseline record is the commit, and drift is re-captured
  deliberately, not continuously.
