# Research: Salmon Wallet design system in Pencil

**Feature**: 041-pencil-design-system | **Date**: 2026-10-09

Facts marked **verified** were run on this machine (pen CLI 0.3.11, logged in)
on 2026-10-09; the probe files live only in the session scratchpad. The rest
are read from the repo or from Pencil's own `read_skill` guides.

## R1 — Library import and themes across files (verified)

- **Decision**: One library file `Salmon.lib.pen` holding every variable and
  component; `Salmon Screens.pen` imports it with
  `import_library({ path: "Salmon.lib.pen" })`. Screens set the theme with the
  library's namespaced axis: `theme: { "<alias>:mode": "light" }`.
- **Rationale**: Probe: a `Button/Primary` component bound to a themed colour
  variable in `Kit.lib.pen`, imported into a second file, appears there as
  `V:<id>` (`imports: { V: "Kit.lib.pen" }`). A frame with
  `theme: { mode: "light" }` did **not** flip the imported instance; the
  consumer's theme list read `{"V:mode": [...], "mode": [...]}`, and a frame
  with `theme: { "V:mode": "light" }` did flip it (PNG export checked). The
  `components.md` guide line "you cannot reference components across files" is
  outdated for 0.3.11 — `imports` works.
- **Consequence**: The alias is generated by Pencil on import, so builder
  scripts read it from the document (`imports`) instead of hard-coding it.
  The screens file declares no theme axis of its own.
- **Alternatives**: One file for everything (rejected: the library must be
  importable by future screen files, and one file means one writer at a time
  for all work); per-flow screen files (deferred: one screens file is enough
  for six flows).

## R2 — Token pipeline source and shape (verified)

- **Decision**: Read tokens by executing the theme module, not by parsing it:
  `createSemantic('dark')` and `createSemantic('light')`, `palette`, `colors`,
  `gradients`, `spacing`, `borderRadius`, `componentSizes`, `contentPadding`,
  `borderWidth`, `opacity`, `blur`, `fontFamily`, `fontSize`, `lineHeight`,
  `fontWeight`, `letterSpacing`, `shadows`, `durations` from
  `packages/shared/src/theme`. Run with the repo's own `jiti`
  (`node_modules/.bin/jiti`), which resolves extensionless TS imports — no new
  dependency.
- **Measured shape**: semantic = 91 leaves (63 hex, 20 `rgba()`, 8 numbers);
  palette = 39 leaves; 55 semantic leaves differ between dark and light; 55
  dark values match a palette step exactly (aliasable).
- **Alias rule**: a semantic leaf becomes `"$palette.<ramp>.<step>"` when its
  value equals a palette step in that mode; otherwise it holds the literal.
  Values built with `withAlpha(step, a)` become `#RRGGBBAA` literals (Pencil
  has no alpha-on-alias), with the source step recorded in the variable
  manifest so the chain is still readable.
- **`rgba()` → `#RRGGBBAA`**: round `a × 255` to the nearest integer, two
  upper-case hex digits.
- **Naming**: the variable name is the token path with dots
  (`semantic.surface.shelf`, `spacing.lg`, `typography.body.size`), matching
  the `--sw-*` path in `packages/ui/src/theme/cssVars.ts` one-to-one.
- **Not variables**: functions (`createSemantic`, `withAlpha`,
  `getScalesColorForBlockchain`), brand path data, the onboarding grid tables
  (they become component measurements), animation curves.
- **`colors` (legacy)**: still the source most components read
  (`theme/index.ts`), so it is exported too, as `colors.*`, aliased to
  `semantic.*` or `palette.*` where values match. Every `colors.*` binding
  in a component is also a finding of kind `legacy-token` (low severity).

## R3 — What Pencil cannot bind (from the `pencil-pen-dev` skill, 0.3.11)

- `width`/`height` bound to a variable are dropped by the CLI: write the
  number, and record the variable name in the component's `context` note so
  the lint (R9) accepts it.
- No `alignItems: stretch` → the stretched child carries `fill_container`.
- No `margin` → parent `gap` or `padding`. No percentage sizes.
- No variant system → one component per variant, `Group/Variant`.
- Text styles are not composite: each typography style is split into
  `.family/.size/.weight/.line-height/.letter-spacing` variables and all five
  are bound.
- Gradient fills (`linear`, `radial`, `angular`, mesh) take colour variables
  per stop; `background_blur` and `shadow` effects take variables. That is the
  palette for FR-012 (water column, thermocline, scales, flesh) — no scripts or
  shaders, per the clarification.

## R4 — CLI automation quirk (verified)

- **Decision**: All pen automation goes through a bash wrapper (shebang
  `#!/bin/bash`) that JSON-encodes the builder script and pipes
  `execute({ input: ... })`, `save()` and `exit()` into
  `pen interactive -i <in> -o <out>`.
- **Why**: zsh's `echo` expands `\n` inside the JSON-encoded string and
  breaks the command into invalid lines (seen in the probe). The root node is
  the predefined `document` (not `null`); every inserted node needs `name`.

## R5 — Extension containers (read from `apps/extension/wxt.config.ts`)

- The toolbar opens the **side panel** (`side_panel.default_path`); the
  manifest's `default_popup` is deleted on purpose. `popup.html` is only the
  dApp-approval window the background opens with `windows.create`.
- **Decision**: extension templates are _Side panel_ (main surface, measured
  at Chrome's default side-panel width) and _Approval popup window_, plus the
  extension sheet/modal (a `<dialog>`, per the parity map's
  `BottomSheetTitleHeader` note). Spec FR-009 was corrected to say this.

## R6 — Runtime measurement

- **Extension (Playwright, headless)**: reuse the suite's fixtures
  (`apps/extension/.playwright/fixtures.ts`, `helpers.ts`, test wallet from
  the gitignored `.env.test`) the way `scripts/store-shots.mjs` already does.
  For each captured state: a full-surface screenshot plus, for every element
  carrying `data-testid` and every kit-component root, `getBoundingClientRect()`
  and the computed `display`, `flex-direction`, `gap`, `padding-*`,
  `margin-*`, `position`, `width`/`height` (and whether they were set
  explicitly), `align-items`, `justify-content`, `font-*`, `color`,
  `background-color`, `border-radius`.
  **Debt candidates are flagged automatically**: non-zero margin between flex
  siblings, `position: absolute` outside overlays, a fixed px width/height on a
  child of a flex container, a colour not present in the token set.
- **Mobile (Maestro, iOS Simulator)**: Maestro exposes bounds and
  accessibility ids, not styles. Per captured state: `takeScreenshot` and
  `maestro hierarchy` (bounds per `testID`). Spacing between elements is
  derived from bounds; the structural cause is read from the RN source of the
  twin. iPhone 15/16 class (390×844 pt) is the reference frame, the same size
  the existing `product.pen` drawings use.
- **Flows reused**: `.playwright/tests/{onboarding-grid,send,receive,settings}`
  and `.maestro/flows/smoke/{auth,home,send,receive,settings}` already reach
  every key-flow state except Swap; the Swap capture is a new script/flow in
  the audit harness (§R10), driven to the quote/review state only — never to
  broadcast.
- **Safety**: test wallets only, secrets from the gitignored env files, no
  broadcast, screenshots never of the seed reveal (the onboarding seed board is
  drawn with the public `abandon…` vector as demo data).

## R7 — Component inventory and classification

- **Universe**: `packages/ui/src/components` (116 folders), their mobile twins
  in `apps/mobile/src/components`, the contracts in
  `packages/shared/src/types/ui` (86 files), and the platform maps
  `MOBILE_ONLY`, `DOM_ONLY`, `MOBILE_ONLY_SCREENS` in
  `scripts/check-dom-parity.mjs`.
- **Classes**: `primitive` (no kit component inside), `composite` (built from
  kit components), `container` (sheet/dialog/panel/layout — becomes a
  template), `page` (drawn as a screen, not a library component — spec
  assumption), `motion-wrapper` (SinkFloat, FadeThrough, PressSpecular — not
  drawn; noted), `material` (DepthBackground, WaterColumn, Thermocline,
  ScalesBackground, FleshBackground — native approximation per FR-012).
  Plus `platform`: `both | mobile-only | extension-only`, and
  `in-key-flows: yes|no`.
- **First pass with Jev** (`typesafe:typesafe-ai`, `$TYPESAFE_API_KEY`): input
  per component = folder name, its `types.ts` props, the list of kit imports in
  its source, and its parity-map note if any; output = class + platform + a
  confidence. The main model then reviews every answer under the confidence
  threshold and a 20% sample of the rest; `in-key-flows` comes from the import
  graph of the key-flow pages, not from Jev. The repo is public, so sending its
  component code to the classification API exposes nothing new.
- **Library scope** (FR-003): components with `in-key-flows: yes` whose class
  is primitive, composite or material. Others are listed in the inventory but
  not drawn in this pass.

## R8 — Fonts

- Shipped DM Sans is a modified build (digit advances equalised,
  `packages/assets/src/fonts/DMSans-README.md`); Geist Mono for addresses and
  phrases. Pencil renders `fontFamily` only if installed: the owner installs
  the shipped TTFs into Pencil (human step) before any PNG comparison counts.
  Headless exports before that fall back to a substitute font and are not
  compared.

## R9 — Verification tooling

- **Variable lint**: a builder-style script that walks every component and
  board (`Get(visitor)`) and prints each `fill`, `stroke`, `gap`, `padding`,
  `cornerRadius`, `opacity`, `fontFamily`, `fontSize`, `fontWeight`,
  `lineHeight`, `letterSpacing` and effect colour that is not a `$variable`;
  sizes are accepted only when the node's `context` names the size token.
  Exit criterion: zero lines (SC-001).
- **Visual check**: `Export([ids], "png", dir, { scale: 2 })` per component
  board and per flow board, both themes; compared with the runtime screenshot
  of the same state by overlaying and by the per-element bounds from R6
  (tolerance 1px templates, 2px flow elements — spec SC-003).
- **Coverage check**: the token manifest (R2) diffed against
  `GetVariables()` — every token path present, both modes set (SC-002).

## R10 — Where the tooling lives

- **Decision (owner, 2026-10-09)**: in the private SOT,
  `03-dev/Design System/tools/` (token exporter, builder scripts, lint, audit
  capture scripts, pen wrapper). The scripts take the frontend checkout path
  as an argument and import the theme and the e2e fixtures from there.
  Nothing is added to this public repo beyond the spec, and the tooling can
  reference unreleased screens.
- **Rejected**: committing the exporter and capture scripts here so CI could
  check token drift — possible later, not part of this feature.
