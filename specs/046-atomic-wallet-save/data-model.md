# Data model: atomic wallet save (spec 046)

No record changes shape and no key is added. This file lists the records a wallet change touches, their role in the write orders (plan.md §The write orders), and the in-between states the next launch must show correctly.

| Wallet list                  | `salmon_accounts`                                        | `StoredAccount[]`                                     | **Deciding write** of add, remove, edit; a thrown write is settled by reading it back on the extension and is a failed write on mobile (Rule 2). Not an array, or absent/`[]` while memory holds wallets → reject (Rule 1)                                                                                                                                                                                                                          |
| Vault                        | `salmon_mnemonics`                                       | encrypted `LockedVault`; cleartext for unprotected v2 | Before the list on add; after it on remove; replaced Seed Vault entries leave after the list. ## Held positions of a phrase wallet

`StoredAccount.pathIndexes` maps each network id to an array where slot i holds i or `null`. Held positions = every non-null value in every array. Starting position = the smallest held position. Positions grow later through mirror networks and derived-account edits; the duplicate rule tests a new start against the whole held set.

## Secret identity

| Kind        | `DuplicateAccountError` when (own id excluded)                                    | Replaced                                     |

| Phrase      | a listed phrase wallet with an equal phrase after normalising holds the new start | —                                            |

## States the next launch may meet

| Stored state                                       | Produced by                                                                                                                                                                    | Next launch                                                                                                                    |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| Vault, list absent or `[]`                         | first save stopped after its vault; reset stopped after its list write; last listed wallet removed while unlisted entries remained; failed "Remove all"; interrupted migration | extension: lock screen, the vault's password opens the setup screens; mobile: welcome with no reset, setup needs that password |
| Vault key present but unparseable, a wallet listed | corruption (follow-up ticket for a way out)                                                                                                                                    | nothing removed; add and remove reject                                                                                         |
| Vault unparseable, no wallet listed                | corruption                                                                                                                                                                     | the next setup overwrites it, as today                                                                                         |
| List present, not an array                         | corruption                                                                                                                                                                     | loader error as today; every mutation rejects                                                                                  |
| Unlisted vault entry                               | save stopped before its list; Seed Vault replace stopped before its last vault write; removal's vault write failed                                                             | invisible, kept; harmless ciphertext                                                                                           |
| Active id not listed; unheld pair; counter behind  | stops after the list                                                                                                                                                           | fallback, healing, `max` rule at the next save                                                                                 |
| Stale mark                                         | failed or stopped save                                                                                                                                                         | kept until the next save prunes it                                                                                             |

## Invariants asserted after every failure and every kill

1. Every listed id has its vault entry (FR-017).
2. Every entry present before is still there, except the replaced Seed Vault entries after the list and the removed wallet's entry; a save removes nothing else; an entry under a save's own id changes only to the same secret (FR-016).
3. Before the deciding write: wallets, secrets, active wallet, slot, counter, password and memory as before. After it: wallets and entries as after; active = previous (or new if its selection landed) on a held slot; counter right or one behind (FR-001, FR-004, FR-005).
4. A resolved mutation left storage with the change. After a rejected one whose list write threw, the memory refresh wrote nothing; when its reads succeeded, memory equals what storage holds; when its list read came back null or failed, memory is unchanged (`useAccountsLoader.ts:85-89` returns early).
5. At most one listed wallet per secret identity (FR-010).
6. A listed `unconfirmed` wallet is marked; after the next save every mark is named by a listed `id` or `derivedFrom` (FR-018, FR-019).
7. A vault is never re-encrypted under a key a supplied password does not derive (FR-005).
